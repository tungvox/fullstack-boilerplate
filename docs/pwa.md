# Progressive Web App (PWA)

This app ships as an installable PWA using:

- **Web app manifest** — [`src/app/manifest.ts`](../src/app/manifest.ts) (served at `/manifest.webmanifest`)
- **Service worker** — generated by [`@ducanh2912/next-pwa`](https://www.npmjs.com/package/@ducanh2912/next-pwa) into `public/sw.js` during **`npm run build`**
- **Icons** — [`public/icons/`](../public/icons/) (`icon-192.png`, `icon-512.png`). Regenerate after rebranding with `npm run generate:pwa-icons` (requires `sharp` in devDependencies).

## Development vs production

- **`next dev`:** the service worker is **disabled** (`disable: development` in [`next.config.ts`](../next.config.ts)) so caching does not fight hot reload or auth.
- **`next build`:** must use **Webpack** because the PWA plugin hooks Webpack. This repo sets `"build": "next build --webpack"` in [`package.json`](../package.json).

## Caching rules

Extra Workbox rules keep **Supabase REST** and **`/api/*`** on the network (`NetworkOnly`) so session and webhooks are not served stale from a cache. Default runtime caching from the plugin is still applied (`extendDefaultRuntimeCaching: true`).

## Verifying installability

1. Run a production build and start: `npm run build && npm run start`
2. Open the site in Chrome → **Install app** (or Lighthouse PWA audit).

## Deploying (Vercel)

Vercel runs `npm run build`, which emits `sw.js` and `workbox-*.js` under `public/`. Those generated files are **gitignored**; they appear only in build output and deployment artifacts.
